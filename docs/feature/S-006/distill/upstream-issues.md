# S-006 DISTILL: upstream issues

No blocker and no contradiction. The expected goldens of ADR-0011 (seed 31 fixtures 0-3 and seed 20260 fixture 0), its canonical calibration figures and the ADR-0010 goldens all reproduced exactly against a throwaway implementation that followed the ADRs' draw order, so no test was adjusted to fit code. Four observations for DESIGN's and DEVOPS's records (item 4 changes DELIVER's work and is the only one that is not low):

1. **ADR-0011 "any change to constants shifts a golden" is not true for every constant.** Changing only `MAX_CONVERSION` from 0.30 to 0.31 moves none of the five expected goldens (no draw falls between the two thresholds on those fixtures) and stays inside every D7 bound. DESIGN also says the calibration assertions are "the D7 bounds, not the exact figures". DISTILL kept the D7 bounds as the contract and added one deliberate freeze tripwire to `match-calibration.test.ts`: the ADR's own canonical figures recomputed exactly (10901 goals over 8000 side-results, the 0 to 6 goals histogram `[1914, 2864, 2032, 871, 245, 64, 10]`, 220 goalless of 4000, home 1.384, away 1.342, lowest-rated XI 0.481 at three decimals, strength gap mean 64.5 and minimum 27). The seeded fault `MAX_CONVERSION = 0.31` is caught by it and by nothing else. Any later model change needs the ADR-0011 amendment the ADR already requires, and that amendment must update the tripwire.
2. **Browser proof of the awkward-name probe uses seeds found by the reference run.** DESIGN names no seed whose goals include an apostrophe or hyphen name. The e2e uses seed 8 club index 0 ("20' Brannock O'Garrity", Kettlewick Albion 2-2 Pennyfold Wanderers) and seed 6 club index 1 ("Zander Fitch-Moreton", three goals); `match.test.ts` pins both as honesty probes (the same role as the seed 8 fixture 3 goalless pin). They are fixtures for text fidelity, not model expectations: the model itself is held by the ADR goldens, which the same run matches.
3. **The "no sideways scroll" yardstick of the older e2e specs is blind under the Pixel 7 profile.** `tests/e2e/S-001..S-005*.spec.ts` measure `document.documentElement.scrollWidth - window.innerWidth` (the S-006 DEVOPS row already says `scrollWidth <= clientWidth`, which is the sound form). Under mobile emulation `window.innerWidth` grows with overflowing content (measured with a seeded `white-space: nowrap` on the score line: `scrollWidth` 549, `innerWidth` 549, `clientWidth` 390), so that difference stays 0 and the seeded overflow passed. The S-006 specs measure `scrollWidth - clientWidth` instead (the seeded fault is then caught). No existing test was edited; a later story may harden the older specs.
4. **An existing e2e test counts the club-home buttons, contrary to the DESIGN reuse analysis and the DEVOPS coexistence matrix.** Both say "no club-home button count is asserted" and mark `tests/e2e/S-001..S-005*.spec.ts` "reuse unchanged". In fact `tests/e2e/S-005-starting-xi.spec.ts` line 173, "Starting XI is the last of three club home buttons, after Squad and Tactics", asserts `["Squad", "Tactics", "Starting XI"]` exactly. With the S-006 "Play match" button (DISCUSS D1, locked) it fails (the scratch reference run: 101 passed, that one failed; everything else, including S-004 and S-005 club-home regressions, passed). DISTILL may not edit an existing test, so the committed tree is green today and the fix belongs to DELIVER step 04, in the same commit as the button: change that expectation to `["Squad", "Tactics", "Starting XI", "Play match"]` and its title to "four club home buttons" (a superseded count, strengthened rather than weakened; `docs/feature/S-006/distill/pending/e2e/S-006-match.spec.ts.pending` EA13 asserts the same four). The protected scenarios are said by the plan run not to count buttons, and the acceptance tests of S-001..S-005 passed unedited in the same run.
