## U-3 (informational): the S-008 vitest files take about 5 seconds, and the 100-run properties are the cost
`season-progression` 4.1 s, `season-for-a-club` 3.8 s, `season-end` 0.6 s, `season-schedule` 1.4 s (the 1000-seed name guard) on the scratch reference. DEVOPS open question 3 (nightly Stryker re-runs these per `state.ts` mutant): the three whole-season properties use fast-check's default 100 runs; the `nextMatchday` identity property uses `numRuns: 25` and the 80-action property `numRuns: 100`. If the first nightly nears 45 minutes, trim `numRuns` of the whole-season properties in `season-for-a-club.test.ts` first, not the exhaustive schedule check.

## U-4 (informational): the "Season over" line is not focusable, so a click on it blurs the heading
In the scratch run, tapping the "Season over" line takes focus off the club-name heading (a click on a non-focusable element blurs the active element). That is correct browser behaviour and not a defect: the line is plain text (ADR-0014 decision 4). The held-out e2e therefore checks focus after every navigation (where the shell focuses the new `<h1>`) but not after clicking the line. No DELIVER action.
