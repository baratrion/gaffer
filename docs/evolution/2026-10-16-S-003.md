# S-003: View a player's details (evolution record)

Finalized 2026-10-16. Delivery history stays in `docs/feature/S-003/` (feature-delta, slices, `deliver/roadmap.json`, `deliver/execution-log.json`).

## Summary
Sam taps a squad row and sees the player: name as the only `h1`, Position, Age and Overall (equal to the row), a list named Attributes (goalkeeping, defending, passing, shooting, each 1-20), and a Condition N% line (75-100). Back returns to the same squad, and Back again to the club home. One tap each way. Same seed gives identical player screens.

## Key decisions (ADR-0006)
- Attributes and condition come from a separate stream, `deriveSeed(seed, 100 + clubIndex)`, 5 draws per player, so names, positions and ages stay identical to S-002.
- Overall is derived, not drawn: `deriveOverall(position, attributes)` with non-negative per-position weights summing to 10, round half up, so it lies between the lowest and highest attribute.
- Squad rows become exactly one button per list item (44px or taller); the S-002 e2e test was renamed, never deleted.
- `update` gained `ViewPlayer` and `Back` from the player screen, split into per-action helpers (oxlint complexity cap 15); invalid club or index is a no-op.
- `src/app/state.ts` added to the Stryker mutate list. Mutation is nightly-delta; `/nw-deliver` Phase 5 skipped.
